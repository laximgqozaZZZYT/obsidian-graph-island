## Security Audit Summary (`pnpm audit`)

10 advisories: **4 high, 6 moderate** — all in dev/build-time dependencies,
none in runtime/shipped code (esbuild externals + obsidian/electron are not
bundled per CLAUDE.md build config).

| Package | Severity | Issue | Fix |
|---|---|---|---|
| `picomatch` (via typescript-eslint→tinyglobby) | High | ReDoS via extglob quantifiers (CVE-2026-33671) | Upgrade to ≥4.0.4 |
| `vite` (via vitest) | High | `server.fs.deny` bypass via query params (CVE-2026-39364) | Upgrade to ≥8.0.5 |
| `vite` (via vitest) | High | `launch-editor` NTLMv2 hash disclosure (Windows-only) | Upgrade to ≥8.0.16 |
| `vite` (via vitest) | Moderate | Path traversal in optimized-deps `.map` handling (CVE-2026-39365) | Upgrade to ≥8.0.5 |
| `picomatch` (via typescript-eslint→tinyglobby) | Moderate | Method injection in POSIX char classes (CVE-2026-33672) | Upgrade to ≥4.0.4 |
| `esbuild` | Moderate | Dev server CORS allows any origin to read responses | Upgrade to ≥0.25.0 |
| `brace-expansion` (via eslint→minimatch) | Moderate | Large numeric range defeats DoS protection | Upgrade to ≥5.0.6 |

None are exploitable in the shipped `main.js` (dev-server / build-tool only),
so risk is limited to local dev workflows. `vitest`/`typescript-eslint`/`esbuild`
bumps are low-risk since they're devDependencies pinned independently of the
Obsidian runtime API.

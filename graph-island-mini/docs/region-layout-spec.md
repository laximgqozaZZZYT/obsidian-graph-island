# 集合・積集合ダイアグラム レイアウトアルゴリズム仕様 (確定版 v2)

> 本書は、ノードが複数の集合に所属するデータを、各集合・各積集合を「囲み（領域）」として描画し、囲みの中にノードを配置するダイアグラムのレイアウト計算手順を定義する。実装担当者は本書のみで実装可能なように記述してある。

---

## 0. 設計前提（確定事項）

- **囲みの形状は、すべての集合・すべての積集合とも「軸並行矩形（AABB, 各辺がx軸/y軸に平行、コーナー90度、回転なし）」とする。面積は可変。**
- 軸並行矩形どうしの交差は、必ず軸並行矩形（または空）になる。したがって積集合の囲みも自動的に軸並行矩形になり、集合と積集合を同一の型・同一の計算で扱える。多角形は一切登場しない。
- **非積集合（基底集合）は必ず1個以上の要素を持つ**ものとする。よって基底集合の囲みは必ず正の面積を持つ。
- **積集合は空（要素数0）になりうる。これを許容する。**
  - AABB の Helly 数は 2。`k` 個の AABB について全ペアが重なるならば全 `k` 個が共通領域を持つことが幾何的に強制される。これは `k = 3, 4, 5, …` 全てで成立。
  - 「対は重なるが共通要素は0」の `k`-重領域に正の面積が出ることは**仕様通りの正常な挙動**であり、空の積集合の囲みとして正当に描画する。
  - **したがって実現可否ゲート（Hellyチェック）・空ゾーン罰項・フォールバック（極小化、空印、対の切り捨て等）はいずれも不要であり、実装しない。** 件数0の積集合ゾーンは、目標面積が小さいだけの普通のゾーンとして連続的に扱う。

---

## 1. 用語・記号

- **ノード（node）**: 配置対象の最小単位。1つ以上の基底集合に所属する。
- **基底集合（base set）**: 入力で与えられる集合。記号 `A, B, C, …`、総数 `n`。
- **NONE_BUCKET**: どの基底集合にも所属しないノードを束ねる**特別な基底集合**。一個以上のノードを持つ場合のみ実体化される。他基底集合との関係は常に「分離要」(= どのゾーンとも共存しない)。
- **積集合（intersection）**: 2つ以上の基底集合の共通部分。例 `A∩B`。
- **ゾーン（zone）**: ノードの「所属組合せが完全一致する最小領域」。あるノードの所属が `{A,B}` ちょうどなら、そのノードはゾーン `{A,B}` に属する。ゾーンは互いに素で、全ノードを一意に分割する。
  - 単一集合ゾーン `{A}` = 「Aにのみ属する」排他領域。
  - 複数集合ゾーン `{A,B}`, `{A,B,C}` = 積集合の排他部分。
  - 集合Aの囲み = 「Aを含む全ゾーンの和」。
- **囲み（enclosure）**: 集合または積集合を表す軸並行矩形。矩形 `i` を `[xᵢ, xᵢ+wᵢ] × [yᵢ, yᵢ+hᵢ]` で表す（変数は `xᵢ, yᵢ, wᵢ, hᵢ` の4つ）。
- **広がり（extent）**: あるゾーン/集合が x軸（または y軸）方向に占める長さ。
- **多重所属ゾーン**: `|zone| ≥ 2` のゾーン（=積集合の排他部分）。
- **排他ゾーン**: `|zone| = 1` のゾーン（=単一集合の排他部分）。
- **Helly 強制ゾーン**: 任意 `k ≥ 3` 個の基底集合 `S` で、`S` 内の全ペアが「重なり要」かつ件数 `count(S) = 0` のもの。幾何的に正の面積が必ず発生する。

---

## 2. 入力

1. ノード集合 `N`。各ノード `v` は次を持つ:
   - 所属基底集合の集合 `membership(v) ⊆ {A,…}`（0個以上 — 0個の場合は NONE_BUCKET 扱い）。
   - 所属グループ情報（後述のサイズ・カスケード用）。
2. 基底集合の一覧と、各集合の属性:
   - **継承元グループ** (`inheritFrom`): ユーザー設定。設定の継承元と視覚的内包 (nesting) の両方に作用する。
   - **上位集合** (strict superset): メタデータから自動算出。
   - 集合に紐づくグループ設定。
3. サイズ設定テーブル（グループ単位／全体）。各設定はノード1個の表示サイズ（辺長または面積）を与える。
4. 集合間の関係（上位・下位、継承）が分かるメタデータ。
5. **Aggregate flag**: 基底集合単位の boolean。true の場合、その集合は 3-card stack で折りたたみ表示。

---

## 3. 設定パラメータ（既定値つき）

| 記号 | 意味 | 既定値 |
|---|---|---|
| `ρ` | 充填率（領域面積に対する実効ノード占有率）。矩形ノード＋ガター g=0.18·辺 を仮定した値。円ノードなら ×0.785。 | `0.72` |
| `g` | ノード間ガター（辺長比） | `0.18·sᵢ` |
| `p` | 集合矩形の内側パディング（各辺）。**ゾーン目標面積には加算しない**。 | `0.5·s̄`（s̄=平均ノード辺長） |
| `t` | 集合矩形上部のラベル帯（積集合矩形には付けない） | `1.5 行高` |
| `minGap` | 件数≥1ゾーンの各軸方向の最小幅（ノードが必ず1個入る幅） | `s̄ + g` |
| `weightₛ` | ゾーン/集合 S の面積誤差の重み | 件数に比例（多いゾーンほど重く）。基底集合は `Σ_{zone⊆S} count(zone)` |
| `λ_topo` | 位相ペナルティの重み | `max(weightₛ) × 100` |
| `emptyZoneTargetMode` | 件数0の積集合ゾーンの目標面積。`minimal`=自然強制ぶんのみ（罰なしで成り行き）／`visible`=隣接有要素ゾーンに馴染む正の面積を積極付与。**既定 `minimal` 確定。** 設定として外出しし、ユーザーが切替可能。 | `minimal` |
| `maxOuterIter` | 外側反復（面積補正）の上限。N≥50 の大規模 vault では `2` に減衰させる (実装で動的判定)。 | `5` |
| `maxInnerIter` | 交互最適化の上限 | `50` |
| `innerTol` | 内側反復の収束判定（目的関数の相対変化） | `1e-3` |
| `outerTol` | 外側反復の収束判定（目標面積の相対変化） | `5e-2` |
| `gradStep0` | projected gradient の初期ステップ | `0.5` |
| `gradMaxStep` | projected gradient の 1 反復あたり最大変位 | `s̄` |
| `seedShuffleTries` | Phase D の seed 再シャッフル回数 (Phase E-6 で発火) | `3` |
| `aggregateStackSize` | Aggregate されたクラスタを Phase A で何個の仮想ノードに置換するか (= 3-card stack の表示要素数) | `3` |

**ハッシュ関数**: 決定性が必要な場面 (Phase D の seed、Helly 強制ゾーン判定の sort key 等) では **FNV-1a 32-bit** を使用。既存 `subgroupHashOffset` と同一実装を流用。

---

## 4. 出力

- 各囲み（基底集合・積集合）の矩形 `(x, y, w, h)`。
- 各ノードの座標。
- 各ゾーンの目標面積に対する達成残差（診断用）。
- 各 Aggregate された基底集合に対する stack 描画情報 (中心座標 + 折りたたまれた member 数)。

---

## 5. アルゴリズム

### Phase A — ゾーン分解と件数集計
1. **Aggregate 前処理**: Aggregate flag = true の基底集合 `X` について、`X` に属する全ノードを Phase A 入力から除外し、代わりに `membership = {X}` の仮想ノードを `aggregateStackSize` 個 (=3) 追加する。仮想ノードのサイズは集合 `X` のグループ設定で決まる。
2. **NONE_BUCKET 処理**: `membership(v) = ∅` のノードを集めて、`membership = {NONE_BUCKET}` に書き換える。NONE_BUCKET を基底集合一覧に追加。
3. 各ノード `v` を、`membership(v)` をキーとするゾーンへ振り分ける。
4. 件数1以上のゾーンのみ実体化する（`2ⁿ` の全列挙はしない。出現した組合せのみ生成）。
5. 件数を集計する: `count(zone)`。基底集合 `A` の件数 = `Σ count(zone) over { zone : A ∈ zone }`。前提により ≥1 が保証される。
6. **Helly 強制ゾーン検出** (任意 `k ≥ 3`): 全ペアが「重なり要」(= 何らかの非空ゾーンを共有) かつ件数 0 の組 `S` を列挙する。実装上は、非空ゾーンから抽出した membership 集合の全 sub-set (要素数 `≥ 3`) を走査し、件数 0 のものを抽出する。これらは Phase E で正の面積が自動的に出るが、件数 0 として扱う (= `minGap` を課さない、罰も課さない)。

### Phase B — ノード面積算定（サイズ・カスケード）
各ノード `v` の表示サイズを、次の優先順位で**最初にヒットした設定**で決定する:

1. **所属グループ設定**。`v` が複数グループに属する場合は、**`v` の membership 内でクラスタ件数 `count(cluster)` が最大のグループ `C*` の設定を優先**。同数の場合は決定的タイブレーク (グループID辞書順昇順) で `C*` を一意に選ぶ。
2. （未ヒット時）**`C*` の継承元グループ設定**。`C*.inheritFrom` チェインを辿り、最初にヒットした設定を採用。**辿る先が `v` の所属外でも構わない** (= これは「設定の継承」であって「所属の継承」ではない)。
3. （未ヒット時）**`C*` の上位集合グループ設定**。`C*` の strict superset (= `C*` の全メンバーを含む別クラスタ) のうち `count` 最大のもの。複数あれば辞書順タイブレーク。
4. （未ヒット時）**全体 `[全体]` 設定**。

ノード面積 `area(v) = (辺長設定)²`（矩形ノード前提）。カスケードは必ずノード単位で評価し、再現性のためタイブレークを決定的に固定する。

### Phase C — 目標面積算定
- **ゾーン目標面積** (パディングは加えない):
  - 件数≥1: `target_area(zone) = (Σ_{v∈zone} area(v)) / ρ`
  - 件数0 (積集合のみ、Phase A-6 で検出): `emptyZoneTargetMode` に従う。
    - `minimal`: **目標面積項そのものをスキップ** (= weight=0)。1D solve で minGap も課さない。Helly により幾何的に発生する面積をそのまま受容。
    - `visible`: 隣接有要素ゾーンの平均面積の 30%。weight は通常ゾーンの 0.2 倍 (弱い引力)。
- **集合の目標面積** = `Σ target_area(zone) over { zone : 集合 ∈ zone }`（含有ゾーンの総和。これにより「集合面積 ⊇ 積集合面積」の整合が自動成立）。
- **集合矩形の最小寸法** = `max(ラベル幅, 最密ゾーンの必要幅/高さ) + 2p`。ラベル帯 `t` を上部に加算。

> 注: 矩形の縦横比によって必要面積は変わる（縦長/横長で詰め込み効率が変化）。初回は正方近似で見積もり、Phase F で実形状補正する。

### Phase D — 初期配置（seed）
1. **オーバーラップグラフ**を作る:
   - 2集合が**いずれかのゾーンで共に件数>0**（=要素を共有）なら「重なり要」エッジ。
   - 2集合が**どのゾーンでも共存しない**なら「分離要」関係。NONE_BUCKET は他全てと「分離要」。
   - **`inheritFrom` で関連付けられたペア** (子→親) は「内包要」関係 (子矩形が親矩形の内側、= nesting 制約)。
2. 各集合矩形を `√(集合目標面積)` の正方形で初期化。
3. 「重なり要」エッジで結ばれた集合どうしが重なり、「分離要」関係の集合どうしが離れ、「内包要」関係の子が親の内側に配置されるよう、簡易な力学レイアウト（ばね＝重なり要、反発＝分離要、引力＋内側制約＝内包要）または貪欲配置で初期座標を決める。**乱数は使わず、決定的シードから生成する** (集合 ID 辞書順インデックス + シャッフル試行番号を FNV-1a hash した値で初期座標を導出)。
4. 入れ子関係（`A ⊆ B`: Aの全ノードがBにも属する）が判明している場合は、Aの矩形をBの矩形の内側に初期配置する。

> seed の重なりは初期から浅めに取ると後段の収束が速い。

### Phase E — 交互最適化（座標降下 + 1次元区間配置）
x軸とy軸は交差面積で積として結合する（ゾーン面積 = x方向広がり × y方向広がり）ため、**片軸を固定して他軸を解く操作を交互に反復**する。各軸ステップは1次元問題に縮約される。

```
prev_obj = +∞
repeat (最大 maxInnerIter 回 または 目的関数の相対変化が innerTol 未満):
    # --- y軸を固定して x軸を最適化 ---
    各ゾーン/集合 S について target_len_x(S) = target_area(S) / extent_y(S)
    solve1D(x軸, target_len_x)
    # --- x軸を固定して y軸を最適化 ---
    各ゾーン/集合 S について target_len_y(S) = target_area(S) / extent_x(S)
    solve1D(y軸, target_len_y)
    new_obj = 現在の目的関数値
    if |prev_obj - new_obj| / max(1, prev_obj) < innerTol: break
    prev_obj = new_obj
```

**solve1D（1軸の区間配置） — projected gradient 方式 (gap 1 確定)**:
```
入力: 各矩形の当該軸の区間 [start_i, end_i]、各ゾーン S の目標長 target_len、重み weight
変数: x_i = (start_i, end_i) の 2n 個 (n=基底集合数 + NONE_BUCKET 有無)

1. 区間端点を現在の順序でソートし、連続端点間に「セグメント」を作る。
2. 各セグメントの被覆集合 active(seg) = そのセグメントを覆う基底集合の組 → これがゾーン。
3. ゾーン S の当該軸広がり extent(S) = Σ_{active(seg)=S} len(seg)。
4. 目的関数:
       f(x) = Σ_S weight_S · (extent(S) − target_len_S)²  +  λ_topo · 位相ペナルティ(x)
5. projected gradient で f を最小化:
       step = gradStep0
       repeat (最大 50 回):
           g = ∇f(x)   # 解析的勾配 (各端点について chain rule で計算可)
           x_new = x − clip(step · g, ±gradMaxStep)
           x_new に対し以下の射影を適用:
             - 件数≥1 ゾーンに対応するセグメント: len ≥ minGap になるよう端点を押し広げる
             - 件数=0 ゾーン (Helly 強制): 制約なし
             - end_i ≥ start_i の保証
             - 端点順序の保持 (順序入替なし)
           if f(x_new) < f(x): x = x_new; step *= 1.1
           else: step *= 0.5
           if step < 1e-4 · gradStep0: break
6. 局所改善 (2 段階):
   (a) 隣接端点ペアを試験的に入れ替え、再 projected gradient で目的関数が下がれば採用。最大 5 回。
   (b) **Seed 再シャッフル**: Phase D を異なる hash seed (試行番号インクリメント) で再 init し、Phase E 全体を再実行。最大 `seedShuffleTries` (=3) 回。各試行の最終目的関数値を比較し best を採用。これにより端点順序保持が局所解に閉じ込められても脱出可能。
```

**位相ペナルティ**（`λ_topo · …`、Phase A のオーバーラップグラフに基づく）:
- **重なり要**（要素を共有する集合対）: 当該軸で重ならないと罰 (= `(必要重なり量 − 実際の重なり量)²` のヒンジ)。
- **分離要**（要素を一切共有しない集合対、NONE_BUCKET と他全集合を含む）: 当該軸で重なると罰 (= 重なり量²)。
- **Helly強制ゾーン**: **罰しない。許容する。** (前提0参照、Phase A-6 で検出済み)
- **入れ子**（数学的 subset `A ⊆ B`）: Aが当該軸でBの内側に収まらないと罰 (= Bからのはみ出し量²)。
- **`inheritFrom` 関係** (ユーザー設定): subset と同等の nesting 制約を課す。子矩形が親矩形の内側に収まらないと罰。これにより既存の視覚的 engulf 機能を維持。

### Phase F — 外側反復（面積補正）
矩形の確定形状（縦横比）に基づき、実際の詰め込みに必要な面積を再計算し、Phase C の目標面積を更新して Phase E を再実行する。

```
repeat (最大 maxOuterIter 回):
    Phase E を実行
    各ゾーン矩形 (= 関与する基底矩形の交差結果) の実 width / height を取得
    実形状の縦横比 r = width / height で詰め込み効率係数 ρ(r) を再評価
       (例: shelf-pack シミュレーションで真の必要面積を再計算)
    target_area を更新
    Δ = max_S |new_target − old_target| / old_target
    if Δ < outerTol: break
```

**大規模 vault 緩和**: 基底集合数 `n ≥ 50` の場合は `maxOuterIter` を `2` に減衰させ、settings 変更時の再計算遅延を抑制する。

### Phase G — ノード配置（gap 3 確定: 多重所属優先 + spiral-snap 流用）

1. **多重所属ノード (|zone| ≥ 2) を先に配置する**:
   - 各 zone の幾何的領域 = 関与する全集合矩形の AABB 交差 = 軸並行矩形
   - その矩形内に、当該 zone のノードを左上から行優先で格子配置 (ガター `g`、内側パディング `p` 尊重)
   - 配置済みセルを `occupied: Set<"col,row">` に記録
2. **排他ノード (|zone| = 1) を後に配置する**:
   - 各排他ノードの初期セル = 自分の所属集合矩形の中央
   - `occupied` を尊重しつつ、既存 `snapCardsToGrid` の spiral 探索でフリーセルへスナップ
   - 集合矩形の内側に閉じ込めるため、spiral は集合矩形外を試行しない (= 矩形外セルは無条件 occupied 扱い)
3. **Aggregate 後処理**: Phase A-1 で仮想ノード化した aggregate クラスタの集合矩形に対し、その中央に 3-card stack 描画情報を生成 (中心座標 + 元の member 数)。仮想ノードは描画しない。
4. 検算: 全ノードが「自身が属するゾーンを構成する全集合の矩形の内側」にあること。

> Phase G-1 の幾何的交差矩形は Helly 強制ゾーンでも計算でき、件数 0 なら配置すべきノードがないのでスキップ。

### Phase H — エッジ配線 (既存 `routeZ` を再利用)
集合・ノード配置確定後、既存の orthogonal edge routing (`routeZ` + `LaneRegistry`) をそのまま流用してエッジ経路を計算する。新算法でもノードはセルグリッド上に配置されるため、配線ロジックは無改修で動作する。

## 6. 目的関数と制約（まとめ）

**最小化対象（各 solve1D で）:**
```
Σ_S weight_S · (extent(S) − target_len_S)²  +  λ_topo · Σ(位相ペナルティ)
```

**制約 (projected gradient の射影ステップで強制):**
- 件数≥1 のゾーン: 各軸 `len ≥ minGap`（ノードが必ず1個入る）。
- 件数0 のゾーン (Helly 強制 / `minimal` モード): 最小幅制約なし（成り行きで決まる）。
- 件数0 のゾーン (`visible` モード): weight 弱め (0.2×) の target で引力のみ、minGap は課さない。
- 重なり要の集合対: 重なる。分離要の集合対 (NONE_BUCKET 含む): 重ならない。
- 入れ子 (数学的 subset): 内包。
- `inheritFrom` 関係 (ユーザー設定): 子矩形が親矩形に内包される (= subset 同等の nesting)。

## 7. 実装上の重要注意

1. **空積集合は正常系**。件数0の積集合ゾーンに正の面積が出るのは仕様通り。実現可否判定・空ゾーン罰・フォールバックは実装しない。
2. **Helly 強制ゾーンは任意 `k ≥ 3` を列挙** (問題 1 確定)。三重に限らず四重以上も検出。
3. **基底集合は必ず非空**なので、基底集合矩形には常に `minGap` 由来の下限がかかり、潰れない。
4. **件数0かどうかで minGap の有無を切り替える非対称**が肝。件数≥1にのみ最小幅を課す。
5. **カスケードのタイブレークは決定的に固定**（再現性のため）。Phase B では「`count(cluster)` 最大、同数なら ID 辞書順昇順」と固定。
6. **Phase B-2/3 のチェインは設定継承であって所属継承ではない** (問題 2 確定)。`C*.inheritFrom` の先が v の所属外でも採用する。
7. **ゾーン目標面積にパディングを加えない** (問題 3 確定)。`target_area = (Σ area) / ρ` のみ。パディング `p` は集合矩形の最小寸法計算でのみ加算。
8. **面積は形状依存**（縦横比で詰め込み効率が変わる）ため、Phase F の外側反復を必ず1回以上回す。
9. 不変条件の検算: 「集合のノード面積 ⊇ 当該集合を含む積集合のノード面積総和」「集合面積 = 含有ゾーン面積総和」。
10. `emptyZoneTargetMode` 既定 `minimal`。設定として外出しし、`visible` への切替を可能にする。
11. **Phase D の seed は決定的** (FNV-1a 32-bit、集合 ID + 試行番号から)。乱数を使わない。同入力 → 同出力。
12. **Phase E の projected gradient は自前実装**。外部 QP ライブラリへの依存は導入しない。
13. **Phase E-6 (b) で seed 再シャッフル** (問題 4 確定)。3 回試行して best を採用。
14. **NONE_BUCKET は基底集合の 1 つ** (問題 5 確定)。他基底集合とは「分離要」関係。
15. **Aggregate クラスタは Phase A の前段で 3 個の仮想ノードに置換** (問題 6 確定)。集合面積計算に正しく効く。Phase G-3 で stack 描画。
16. **`inheritFrom` は size cascade と視覚的 nesting の両方に作用** (問題 7 確定)。Phase E の位相ペナルティに「内包要」を追加。
17. **Phase G は既存 `snapCardsToGrid` の spiral 探索を排他ノード配置に流用**。新規パッキング実装は最小限に抑える。
18. **エッジ配線は既存 `routeZ` を流用** (Phase H、無改修で動作)。
19. **既存 `anchorPlacement: "concentric" | "flow"` 設定は Phase D の力学法初期トポロジを制御するパラメータとして残す** (concentric=中央集約、flow=行展開)。UI 削除はしない。
20. **大規模 vault 緩和**: `n ≥ 50` で `maxOuterIter = 2` に減衰。
21. **既存テスト互換性**: 現状の `centroid-collision-test`, `broad-collision-test`, `scale-overlap-test`, `agg-stress-test`, `aggregate-overlap-test`, `layout-smoke`, `query-smoke` は新アルゴリズムでも PASS する必要がある。`multi-tag-spread-test`, `bug1-bug3-diagnose` は出力数値が大幅改善することを期待。NONE_BUCKET / aggregate / inheritFrom 視覚化 (注 14-16) は新算法でも既存挙動を維持。

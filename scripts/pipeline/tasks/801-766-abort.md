## Description (subtask of 766-733-issue-read-frontmatter)

ISSUE_PATH が空文字または `test -f "$ISSUE_PATH"` が偽の場合、
  `[frontmatter-read] missing path, abort` をログ出力し ABORT=1 を立てて
  以降の status 判定タスクを実行しないフロー分岐をタスクファイルに明記。
  Read が 0 行を返した場合も同様に abort。
  Acceptance: 異常系 3 パターン（パス空／不在／0 行）のログ例を Description 末尾に追加。
  実ソース変更なし。最後に frontmatter の status を `in-progress` → `done` に更新して完了マーク。

### Abort flow contract

```
if [ -z "$ISSUE_PATH" ] || [ ! -f "$ISSUE_PATH" ]; then
  echo "[frontmatter-read] missing path, abort" >&2
  ABORT=1
  # 以降の status 判定タスク (737-721-issue-frontmatter-status-done など) を skip
  exit 2
fi

HEAD30="$(node scripts/issue-pipeline/read-frontmatter.mjs "$ISSUE_PATH")"
if [ -z "$HEAD30" ] || [ "$(printf '%s' "$HEAD30" | wc -l)" = "0" ]; then
  echo "[frontmatter-read] missing path, abort" >&2
  ABORT=1
  exit 2
fi
```

### 異常系ログ例 (3 パターン)

1. パス空 (`ISSUE_PATH=""`):
   ```
   [frontmatter-read] missing path, abort (reason=empty-path, ISSUE_PATH="")
   ```

2. ファイル不在 (`test -f` が偽):
   ```
   [frontmatter-read] missing path, abort (reason=not-found, ISSUE_PATH="/abs/path/to/missing.md")
   ```

3. Read が 0 行を返す (空ファイル):
   ```
   [frontmatter-read] missing path, abort (reason=empty-file, lines=0, ISSUE_PATH="/abs/path/to/empty.md")
   ```

いずれのケースも `ABORT=1` を立てた後 `exit 2` で即時終了し、status 判定 (frontmatter `status:` フィールドの diff 検査) を行わない。
